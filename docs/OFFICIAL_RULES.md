# 官方規則與資料來源

- 狀態：10條檢查規則與回歸測試已實作；規則內容仍為DRAFT
- 查核日期：2026-09-01（Asia/Taipei）
- 規則資料版本：`rentproof-tw-rental-rules/1.0.0-draft`

## 1. 使用邊界

本文件把官方規範轉成「資訊差異檢查」，不是法律意見或完整法律審查。規則引擎只能輸出：

- `no_difference_found`：依目前資料未發現文字或數值差異，不代表完整法律審查。
- `possible_difference`：資料中有可定位內容可能與官方規範不同，應人工確認。
- `missing_information`：缺少必要頁面、日期、附件、帳單或可靠抽取結果，不能評估。

規則適用性會受簽約日期、租賃用途、期間、當事人關係及個案事實影響。MVP 面向一般住宅租賃；遇不確定適用範圍時一律回傳資料不足，不自行擴張解釋。

警政／消保的租屋防詐宣導不放進本契約規則庫，也不使用 `possible_difference` 語意；它由獨立的 [詐騙風險訊號規格](FRAUD_RISK_SIGNALS.md) 管理，只產生付款前風險訊號與查證行動。

適用性與規則結果分開保存：`applicable` 才執行規則；`unknown` 強制回傳 `missing_information`；`not_applicable` 留下 skipped 紀錄但不產生結果，絕不能轉成 `no_difference_found`。

## 3. 規則目錄

實際 machine-readable 草案位於 [`rules/official-rules.v1.yaml`](../rules/official-rules.v1.yaml)。下表的「檢查」是產品邏輯摘要，不取代官方原文。

YAML只保存來源metadata、啟用設定、`evaluator_id`、文件化判斷條件與中立模板；實際判斷由allowlisted TypeScript evaluator執行，禁止對YAML自由文字使用`eval`。伺服器必須明確選擇目前展示的規則集合，不得因新增evaluator而靜默改變既有報告。

| ID     | 檢查項目             | 確定性判斷                                                                 | 中立提示                                             |
| ------ | -------------------- | -------------------------------------------------------------------------- | ---------------------------------------------------- |
| RP-001 | 契約審閱期           | 有日數且少於 3 日，或偵測到放棄審閱語意時為疑似差異；缺日期為資料不足      | 確認完整契約交付日、簽約日與實際審閱日數             |
| RP-002 | 廣告承諾不得整體排除 | 出現「廣告僅供參考」或等同排除語意時為疑似差異                             | 請人工確認是否修改整體排除文字，並逐項寫入契約／附件 |
| RP-003 | 租賃範圍與附屬設備   | 檢查地址／樓層／範圍／車位／設備附件；缺欄位只算資料不足                   | 廣告設備未列附件時要求補入名稱、數量與狀態           |
| RP-004 | 租金與完整費用       | 契約容許租期內單方調漲，或費用項目不完整時，分別標疑似差異／資料不足       | 逐項確認租金、管理、水、電、網路、停車與一次性費用   |
| RP-005 | 押金上限與返還       | 以契約月租換算，押金超過 2 個月時標疑似差異                                | 修改押金金額並確認返還／抵充方式                     |
| RP-006 | 按度電費             | 只有同一標的、同一期帳單存在時，才比較約定／實收單價與當期每度平均電價     | 只有固定每度金額、沒有帳單時一律要求補件             |
| RP-007 | 非按度及公共用電     | 非按度收費與本期帳單總額比較；公共用電未併入帳單時，額外收取文字標疑似差異 | 補本期總額與公共設施分攤資訊                         |
| RP-008 | 電費資訊透明         | 電費由承租人負擔時，缺平均電價、度數、總額或公共分攤資訊即資料不足         | 補最近一期電費單，並提示可向台電申辦查詢             |
| RP-009 | 修繕責任與聯絡方式   | 檢查由承租人負責的項目是否逐項約明確認，以及是否有修繕聯絡方式             | 影像只觸發補拍與修繕紀錄要求，不判原因／責任         |
| RP-010 | 租金補貼限制         | 偵測禁止、以申請為條件加租或解約等語意，標為疑似差異                       | 請人工確認是否修改限制文字，並向地政／消保單位確認   |

目前10條規則都有確定性evaluator。展示環境可選擇基本6條，或包含契約審閱期、廣告整體排除、押金上限與返還、非按度／公共用電在內的完整10條。這只是展示設定，不代表任一規則是法律判決。

6個primary source snapshots與3個supporting landing-page snapshots已於2026-09-01凍結並記錄SHA-256。契約範本、電費修正與租金補貼修正以官方原文PDF為primary，HTML說明頁保留作supporting provenance。10條規則的allowlisted TypeScript evaluators、stable reason codes及缺件／日期／定位regression均已實作；YAML自由文字不會被執行。RP-001以明載日數優先，否則只用完整交付日與預定簽約日計算日曆日；可定位的放棄審閱語意優先標疑似差異。RP-002只有可定位的整體排除廣告語意可標疑似差異。RP-005以TWD最小單位字串及`BigInt`核對兩個月押金上限，返還／抵充約定未取得時維持資料不足。RP-007同樣使用精確最小單位比較；缺少同一標的同一期帳單、用電度數、租賃範圍或公共用電分攤資料時一律為資料不足。規則庫仍維持draft，因官方來源需在每次公開展示前重查，且內容尚未經台灣法務審閱；介面必須顯示「規則草案」，不得包裝成正式完整審查或法律意見。

補充產品規則：廣告寫有洗衣機、契約附件未列，仍是 `insufficient_evidence`；只有附件明載沒有或不提供洗衣機，才是廣告／契約 `contradicted`。這是證據分類，不是法律規則結果。

### 專有部分非自然死亡揭露（中立證據檢查）

內政部「住宅租賃契約書範本」附件一租賃標的現況確認書，包含租賃住宅專有部分在出租人持有期間，以及持有前且出租人知悉的期間，是否曾發生兇殺、自殺、一氧化碳中毒或其他非自然死亡情事的分開確認。來源沿用`CONTRACT_TEMPLATE`及其2026-09-01凍結快照；locator為「附件一租賃標的現況確認書：專有部分非自然死亡相關確認項目」。

這不是新增RP合法性規則，也不使用俗稱詞彙作判定。Evaluator只核對兩個期間的明確`yes／no／unknown`與source locator；傳聞、地址搜尋、新聞及模型推測不得產生肯定事實。輸出限`支持／矛盾／證據不足`及取得雙方簽署現況確認書、向出租人／仲介書面詢問、保存可定位來源等行動。不得輸出物件判決、機率、分數、責任、價格影響或黑名單。

同理，廣告與契約的租金或費用數值不同，由 Comparison engine 產生 `contradicted`，不屬於 RP-004 的 RuleCheck 結果。官方規則的結果仍只能是未發現差異、疑似差異或資料不足。

抽取欄位明確區分 `known`、`not_present`、`unknown`。只有完整文件中確認未出現某文字時才可使用 `not_present`；抽取失敗、缺頁或低品質一律 `unknown`，不能當成 `false`。結果 precedence 固定為：有可定位疑似差異 → `possible_difference`；否則資料完整且足以判斷 → `no_difference_found`；其餘 → `missing_information`。

## 4. 電費檢查的必要證據

「每度 NT$5」本身無法證明符合或超過官方計收基準。按度計費至少需要：

- 租賃標的可對應的同一期電費單。
- 當期每度平均電價。
- 當期用電度數與總金額。
- 公共設施電費是否已申辦分攤並併入該標的帳單。
- 契約簽訂日期，以及契約／廣告的計費方式。
- 同一標的、同一期帳單的對應關係必須由文件 reference 或使用者確認，LLM 不得猜測。

缺任一核心比較值時回傳 `missing_information`，提示「尚缺同一期電費資訊，無法核對」，不得輸出「超收」或「符合上限」。

- [內政部新聞與方法說明](https://www.moi.gov.tw/News_Content.aspx?n=2&s=340252&sms=9009)
- [內政部不動產資訊平台：租金統計](https://pip.moi.gov.tw/Publicize/Info/E1080)
- [租金視覺化查詢系統](https://moisagis.moi.gov.tw/rent/index.html)

資料以截至 2026-03-31 的 83.3 萬件租金補貼有效租約為樣本，不代表整體市場所有租約或刊登價。官方提供行政區、租屋型態、屋齡與部分類型的租金總價／單價分布；樣本不足的區隔可能不發布。

RentProof 只能呈現價格脈絡，例如：

> 同行政區／同類型的官方租金補貼有效租約參考分布為 P25、P50、P75；本物件刊登租金位於該分布的＿＿位置。此資料僅供價格脈絡與議價參考，不代表租金合理性判定。

若沒有穩定API，就將官方下載檔轉成帶`source_date`的受控本地資料；不得在prompt中用記憶補值。

## 6. 共通輸出措辭

- 未發現差異：「依目前提供資料，未發現此項文字或數值差異；不代表完整法律審查。」
- 資料不足：「缺少＿＿，目前證據不足，請補件後再核對。」
- 疑似差異：「所提供資料與官方規範文字／另一來源可能不一致，請於簽約前修改或交由地政、消保單位或專業人士確認。」

禁止自動輸出：確定違法、確定無效、確定詐騙、房東超收、房東應負漏水責任、租金不合理。

## 7. 規則更新程序

1. 只從政府官方頁面取得更新，記錄 URL、公告／生效日期與查核日期。
2. 人工比較新舊文字；不得把整份官方文件交給模型後自動發布規則。
3. bump規則版本，更新YAML、本文與回歸測試；保存本次官方來源快照並記錄SHA-256。
4. 用舊版與新版測試資料做regression，確認措辭仍不越過安全邊界。
5. 至少在每次公開展示前重查；正式服務應定期並於來源異動時檢查，來源版本未知時顯示「規則待更新」。
